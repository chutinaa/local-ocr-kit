## 1. 这是干什么的

你有没有核对过几十页的扫描件或 PDF——系统里一份清单，屏幕上一份文档，人眼一行行找、一位位对，看到眼花？想让 AI 代劳，却发现处处别扭：文档涉密，不能传给外部 AI 工具；就算能传，几十页扫描图喂给大模型，token 消耗高得离谱；而且每次都要打开对话、上传文件、描述一遍需求——对一个每天重复的固定动作来说，太重了。

这个项目给你第三条路：**用 Windows 系统自带的本地 OCR 引擎，搭一个轻量级核对应用**——

- **开箱即用**：贴上清单、拖入文档，几秒钟得到三档报告（已匹配 / 需人工确认 / 未找到）；
- **按你的工作流定制**：把你自己的审查规则（找什么、容错多严）导入流程框架，搭出专属于你的核对工具；
- **全程本地**：任何文件、任何数据都不上传，只在你自己的 Windows 电脑上运行。

它对不确定性诚实：OCR 拿不准的一律标「需人工确认」，绝不悄悄算成匹配。

## 2. 我该用哪个版本

| | 网页版 | Windows 增强版 |
|---|---|---|
| 适合 | **先试试**（30 秒上手，零安装） | **日常使用——建议下载这个** |
| OCR 引擎 | 在浏览器里跑（WASM） | Windows 10/11 系统自带引擎（`Windows.Media.Ocr`） |
| 速度 | 慢：实测 4 页扫描件约 53 秒 | 快：同样 4 页约 2.3 秒 |
| 环境要求 | 任何系统的现代浏览器 | 仅限 Windows 10/11 |
| 隐私 | 文件不离开浏览器 | 文件不离开本机 |

两个版本界面、核对引擎、报告完全一样，只有 OCR 这颗"心脏"不同。**不是 Windows？用网页版即可，除了速度其余体验一致。**

没有 Windows 增强包时，网页版自动用浏览器内置 OCR 兜底（仅英文，首次加载约 22 MB，仍然全程本机）。

## 3. 在线试用

打开 **[网页版](https://chutinaa.github.io/local-ocr-kit/)**，点 **Load sample** 看一次虚构数据的完整演示，或直接贴上你自己的清单、拖入文档。零安装，文件不离开浏览器。

## 4. 下载 Windows 增强版

日常使用建议下载这个。到 [Releases](https://github.com/chutinaa/local-ocr-kit/releases) 下载 zip：一个小文件夹（`start.bat`、`winocr.ps1` 和应用文件），**免安装、不需要管理员权限**。双击 `start.bat`，界面不变，OCR 换成系统自带引擎：实测**快约 20 倍**，中文识别更好。要求 Windows 10/11。

## 5. 定制成你自己的工具

三级路径，按成本从低到高选：

| 级别 | 你手里有 | 你要做的 |
|---|---|---|
| 5.1 零配置 | 一份值的清单 | 直接贴进来，一行一个；清单行数自动兼作数量对账 |
| 5.2 场景配置 | 一个固定重复的场景 | 从 `recipes/` 复制一份示例，改几个字段 |
| 5.3 让 AI 帮你 | 独特的系统格式 | 把 `skill/SKILL.md` + 你系统的一段样例文本喂给任何 AI，它替你生成配置 |

5.3 是这个仓库的核心主张：**不会写代码，也能把它拧成你自己的工具。**

## 6. 匹配规则说明

- OCR 文本用容错匹配：只宽恕 5 组真正分不清的字形（0/O/D、1/I/L/T、2/Z、5/S、8/B），其余差异计分、上限 2 分——**宁可多三行"需人工"，不要一次假匹配**。
- Word (.docx) 直接读取原生文字（不经 OCR），因此按**逐字严格**口径判定。
- 数量对账：文档里应有 N 条而实际读到的数目对不上时，先警告、后看表。
- 报告排序把需要人干活的放最上面：未找到 → 需人工 → 已匹配。

## 7. 开发者接口

匹配引擎是零依赖 JavaScript：`import { matchAll } from "./engine/match.js"`。

## 8. 测试与数据声明

仓库内全部示例数据均为虚构。测试套件含阴性对照（随机 ID 必须匹配不上）与篡改自证（故意破坏规则，测试必须变红）。运行：`bun test`。

## 9. 常见问题

**我的文档会被上传吗？** 不会。网页版：一切留在浏览器；Windows 版：一切留在本地进程。

**为什么不直接用大模型？** 三个理由：机密文档往往没有合规通道外发给外部模型；几十页扫描图喂给大模型 token 成本高，而这类核对每天都在发生；审核要求判定可复现，大模型的输出做不到每次一致。确定性规则 + 本地 OCR 三者都满足——零外传、零 token、同样输入永远同样结果。
